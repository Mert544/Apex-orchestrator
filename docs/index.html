Why Apex?

LLM review tools cost money on every PR and answer differently every run. Apex's core is a deterministic reasoning engine — free forever, reproducible, private.

💡

Ideas, not just issues

The Idea Permutation Engine proposes how to develop the project — down to the function: “write behavioral tests for _expand(), complexity 23, never named by a test”.

🔬

A fractal microscope

The zoom stays content-aware for three levels — harden → resource limits → timeout bounds → deadline propagation — and each facet either cites line-level evidence (📌 verified) or stays an honest hypothesis.

🧪

Fixes are proven

Every auto-fix is applied in a sandbox, verified against your test suite, rolled back if anything breaks — and recorded in a proof-of-fix evidence artifact (diff, tests run, durations) you can audit.

🎓

One honest grade

Security · Architecture · Testing · Code debt · Correctness — severity-weighted, fixture-aware, and shallow stub tests get only half credit. An A+ can't be faked.

🔒

Security built in

A canonical AST detector (eval, shell & SQL injection, unsafe pickle/yaml, weak hashes, secrets…) feeds the same idea tree and the Secure phase — with SARIF export for GitHub code scanning. Your development assistant covers the security basics too; no separate scanner needed.

The main idea: it reasons about relationships

A linter hands you separate warnings. Apex sees where problems converge and where they spread — that's the difference between a linter and a brain.

🎯

Convergence (vertical)

When several independent analyses flag the same module — including high-churn, so complex code that recent commits touch most (the classic change × complexity hotspot) — Apex emits one highest-leverage target and opens it into a phased mini-roadmap.

🌐

Theme (horizontal)

When one signal spans many modules — 6 untested files — Apex names it once as a systemic initiative listing the whole affected set, not 6 scattered chores.

🪜

Phased roadmap

Stabilize → Secure → Evolve → Refine: a safety net before you change risky code, secure what's exposed, then grow, then polish — impact/effort/ROI grounded in measured structure.

🧬

It gets wiser

Each applied fix records which idea kinds land cleanly, nudging future scoring toward the lenses with a track record on your codebase — without ever breaking determinism.

See it think

Gate your PRs — free, in 2 minutes

A drop-in GitHub Action: grade the project and review the diff on every pull request. Deterministic, so the gate is fast and reproducible.

# .github/workflows/apex.yml
name: Apex health gate
on: [pull_request]
jobs:
  apex:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: Mert544/Apex-orchestrator@v1
        with:
          min-score: "80"
          base: origin/${{ github.base_ref }}
          fail-on-high: "true"
