## FINDINGS (what the code actually does today, with file:line evidence)

**Session structure.** `run_develop_session` (`app/engine/develop_session.py:630-736`) runs `SESSION_OBJECTIVES` — 10 objectives (`implement-stub, wire-exports, infer-type-hints, dataclassify, modernize, simplify-bool-return, remove-dead-code, dead-params, shrink-functions, inline-helpers`, listed `objective_compiler.py:822-826`) **sequentially**, each its own `compile_objective(...)` call. Inside `compile_objective` (`objective_compiler.py:1797`), the greedy loop (`1982-1994`) calls `candidates(result)` **once per pass** — not once per move; `_run_pass` (`1480+`) lands *every* move in that one scan that still applies before the next pass rescans (comment at `1957-1965` documents this design deliberately). So the number of full rescans is bounded by **pass count**, not move count — but pass count is still driven up whenever moves invalidate each other (dead-param drops, single-module rewrites), and it compounds **across all 10 objectives sharing one process**.

**The one real shared cache — `source_index.py` — invalidates the WHOLE index on ANY single file change.**
`indexed_project()` (`app/engine/source_index.py:173-189`) memoizes a `SourceIndex` keyed by project root, refreshed only when `_fingerprint()` (`152-166`, a sorted `(rel, mtime)` over every `.py` file) differs from the cached one. `SourceIndex.build()` (`82-122`) does a fresh `_py_files` walk + `ast.parse` (line 117, a **raw** `ast.parse`, not routed through the finer-grained cache below) for **every** non-fixture module. Because the fingerprint is a single tuple over the *entire* tree, editing **one** file invalidates the cache for **all ~630 modules**, forcing a full re-walk+re-parse of everything, not just the changed file. `_own_modules()` (`objective_compiler.py:408-418`) is the wrapper most objectives call to reach this cache; call sites: `545, 581, 646, 680, 709, 738, 767` in `objective_compiler.py`, plus `shrink-functions`'s `_extract_suggestions` (`421-441`) via `indexed_project(...).parsed_modules()`, plus `implement-stub`'s cheap scan `_modules()` in `app/execution/objectives/implement_stub.py:519-542`.

**Even where `_own_modules()` is called, most callers throw its cached `source` away and re-read+re-parse from disk anyway — an established fix exists for exactly one sibling but wasn't propagated.**
- `_magic_constant_modules` (`objective_compiler.py:670-683`) is the ONE objective already fixed: it passes `source=src` into `plan_extract_constant(project_root, rel, source=src)`. `plan_extract_constant` (`app/execution/extract_constant.py:373-402`) documents the exact contract: `source` "lets a caller that already has the module's text in hand... pass it straight in, skipping the project-wide `_py_files` walk this otherwise does on every call... byte-for-byte identical" when supplied, disk-read when `None`.
- Every sibling objective built the SAME shape but was never given the same `source=` parameter: `_bool_return_modules` (`646-649`) → `plan_simplify_bool_return` (`app/execution/bool_return.py:171-183`, calls `_read_and_parse` unconditionally, no `source` param at all); `_import_sort_modules` (`704-712`) → `plan_sort_imports` (`app/execution/import_sort.py:178`); `_comprehension_modules` (`733-741`) → `plan_simplify_comprehension` (`app/execution/comprehension.py:189`); `_unused_import_modules` (`762-770`) → `plan_remove_unused_imports` (`app/execution/unused_imports.py:297`). None accepts a pre-fetched source; each re-reads+re-parses the file from disk on every scan, even though `_own_modules()` had it in hand.
- The generic single-file family (`infer-type-hints`, `dataclassify`, `document-signature`, and most `register_module_objective`-registered objectives) shares one plumbing function, `plan_source_rewrite` (`app/execution/cross_file_rename.py:180-217`, disk read at `~207`), whose `transform: Callable[[str], str|None]` signature never receives a pre-parsed tree. `register_module_objective` (`app/execution/objectives/_base.py:33-71`) calls `plan_fn(project_root, rel)` **twice per pass** — once inside `_modules()` (`51-55`, used by `fitness()`) and once inside `moves()` (`61-69`) — even though both calls are scanning the *same* module set on the *same* pass; each call independently re-reads+re-parses.
- `_dead_param_moves` (`objective_compiler.py:311-357`) builds its OWN `source_cache` dict (`330-341`) that reads from disk again instead of reusing the `(rel, source)` pairs `_own_modules()`/`_dead_params()`'s sibling calls already have available.
- `_content_plan` (`498-518`), the wrapper for the tidy/modernize content transforms, re-reads from disk at `505` (`(Path(project_root)/rel).read_text(...)`) even though `_modernize_candidates` (`540-554`) already iterated `_own_modules()`'s cached `source` just to *decide* the move exists (`545-553`) — the move's `build_plan` thunk then redoes the read+transform a second time.

**One objective bypasses BOTH caches entirely — fully uncached whole-project reparse on every single scan.**
`_inlinable_helpers` (`objective_compiler.py:362-366`) calls `suggest_inlines(str(project_root))` with **no `trees` argument**. `suggest_inlines` (`app/execution/inline_function.py:674-725`) explicitly supports an optional `trees` param for exactly this reuse case (docstring at `690-693`: "lets a caller that already parsed the project once... hand the parses straight in, skipping the re-walk + re-parse... left `None` it reads and parses from disk exactly as before"), but the fallback path `_suggest_trees` (`618-632`) does a **fresh, fully uncached** `_py_files(Path(project_root))` walk (reads every `.py` file including tests/fixtures — a *larger* universe than `_own_modules()`) plus `ast.parse(text)` per file, with zero memoization anywhere. This function is invoked at least twice per pass of the `inline-helpers` objective (once via `inlinable_helper_fitness`, once via `_inline_moves`), and once per pass for as many passes as the objective needs.

**A second, independent, finer-grained cache exists and is NOT unified with `source_index`.**
`app/tools/python_structure.py` defines `_TREE_CACHE`/`parse_cached()` (`32-43, 114-139`), keyed per-file by `(absolute_path, st_mtime_ns)` — a strictly *better*-grained design than `source_index`'s whole-tuple fingerprint, since editing one file only invalidates that file's own cache entry. It's used by `_scan_dead_params` (`app/tools/profile_scanners.py:517-546`, via `_collect_dead_param_defs` at `495-515`, `tree = parse_cached(path)` at `507`) — the machinery behind the `dead-params` objective (`objective_compiler.py:297-302`, `_dead_params` → `ProjectProfiler(...).dead_params()` → `project_profile.py:716-725` → `_scan_dead_params`). But: (a) `SourceIndex.build()` calls raw `ast.parse(source)` directly (`source_index.py:117`), never `parse_cached()`, so the same unchanged file gets parsed independently by both subsystems within one session whenever both a `_own_modules()`-backed objective and `dead-params` run; (b) even on a `parse_cached` hit, `_collect_dead_param_defs` still does a fresh `iter_source_files(self.root)` directory walk **and** a fresh `ast.walk`/`tree.body` scan of every cached tree (`_module_object_refs`, `511-514`) on **every single call** — O(n) tree-walk CPU repeated per pass regardless of parse-cache hits, and called at least twice per campaign (`dead_parameter_fitness` at `measure()`, `_dead_param_moves` at each `candidates()`).

**Structural cost model (no timing, call-count reasoning only).** Per SESSION_OBJECTIVES campaign of up to `max_steps=25` passes: `inline-helpers` pays an uncached full-project parse **every** pass (worst case ~25× × 630 modules, no cache credit at all); the `source_index`-backed objectives (`modernize`, `remove-dead-code`, `simplify-bool-return`, `shrink-functions`, plus the sort/comprehension/unused-import family in `ALL_OBJECTIVES`) each pay a full-index rebuild on the **first** pass after *any* other objective in the same session landed a move (shared global cache, one writer anywhere invalidates it for everyone); `dead-params` pays a full directory walk + full AST-tree-walk every pass even when the underlying `ast.parse` is cache-hit; and the `register_module_objective` family (`infer-type-hints`, `dataclassify`, …) pays a disk read+parse **twice per module per pass** (fitness scan + moves scan), independent of `source_index` entirely. This is consistent with, and explains, the recorded observation that `max_steps=1` already costs ~120s and the unbounded run costs 5+ minutes on 630 modules (`docs/PROGRESS.md:12`).

**Distinct, NOT-in-scope cost axis.** `apply_rename` (`app/execution/cross_file_rename.py:783-841`) runs a suite verification (impact-scoped or full) per landed move — this is the *necessary*, by-design verification cost (never-fake-green), separate from the re-parse waste above. Any remediation must not touch this gate; it stays the untouched safety floor. `IdeaPermutationEngine` (`app/engine/idea_permutation.py:70+`) is **not** called anywhere inside `run_develop_session`/`compile_objective` — its `ProjectProfiler(...).profile()` full scan (`235`) is the separate ~161s "idea scout" cost inside `develop_brief`/quickstart (`app/engine/brief_develop.py:207-212`), a different code path from the per-move reparse issue, though `develop_brief`'s subsequent per-objective `compile_objective(..., scope_module=...)` loop (`234-245`) inherits the exact same unscoped `generate(root)` cost described above (`scope_module` filters the *output* list, not the scan itself — `_ordered_candidates`, `objective_compiler.py:1333-1335`).

## PLAN (exact functions to add/change, signatures)

**Stage 1 — lowest-risk shared-cache reuse (wire existing hooks, no new caching semantics).** Byte-identical by construction; each change is additive/optional-parameter, mirroring the already-proven `plan_extract_constant(..., source=None)` pattern.

1. `app/execution/bool_return.py`: `plan_simplify_bool_return(project_root, module_rel, source: str | None = None)` — skip `_read_and_parse`'s disk read when `source` is given (parse the supplied text instead).
2. `app/execution/import_sort.py`: `plan_sort_imports(project_root, module_rel, source: str | None = None)` — same shape.
3. `app/execution/comprehension.py`: `plan_simplify_comprehension(project_root, module_rel, source: str | None = None)` — same shape.
4. `app/execution/unused_imports.py`: `plan_remove_unused_imports(project_root, module_rel, source: str | None = None)` — same shape.
5. `app/execution/cross_file_rename.py::plan_source_rewrite(project_root, module_rel, operator, transform, source: str | None = None)` — the shared single-file plumbing every `register_module_objective`-registered objective (infer-type-hints, dataclassify's siblings, document-signature, …) goes through; skip the disk read at `~207` when `source` is supplied.
6. `app/engine/objective_compiler.py`: update `_bool_return_modules` (646), `_import_sort_modules` (709), `_comprehension_modules` (738), `_unused_import_modules` (767), and their `_*_moves` builder closures to pass `source=src` from the already-iterated `_own_modules()` tuple — the exact edit `_magic_constant_modules` (670-683) already made.
7. `app/execution/objectives/_base.py::register_module_objective`: thread `_own_modules()`'s cached `(rel, src)` into `plan_fn(project_root, rel, source=src)` inside both `_modules()` (51-55) and `moves()` (61-69) — one scan's source reused for both the fitness count and the candidate build, and reused by `plan_fn`'s own optional `source=` param once objectives adopt (5).
8. `app/engine/objective_compiler.py::_dead_param_moves` (311-357): replace the ad hoc `source_cache`/`_module_source` (330-341) with a lookup into `dict(_own_modules(project_root))` — one fetch, already-cached.
9. `app/engine/objective_compiler.py::_inlinable_helpers` (362-366): call `suggest_inlines(str(project_root), trees=<shared trees>)`. New helper in `app/engine/source_index.py`:
   `def all_parsed_trees(project_root: str | Path) -> dict[str, ast.Module]` — returns the union of `indexed_project(project_root).modules`'s already-parsed own trees **plus** a parse of `all_source_texts()`'s residual (tests/fixtures/non-library) entries, so the exact same universe `_suggest_trees(None)` scans today is preserved (no behavior narrowing) while reusing the already-read text (`all_sources`) for every file — zero duplicate disk I/O, and the own-set pays zero duplicate `ast.parse` (already parsed by `SourceIndex.build()`).
10. `app/engine/source_index.py::SourceIndex.build()` (82-122): route the per-file parse through `app.tools.python_structure.parse_cached(path)` instead of a raw `ast.parse(source)` at line 117 — unifies the two independent AST caches so a file already parsed by the `dead-params` scan (or vice versa) in the same session is not parsed twice. Reconcile the except-clause sets first (see RISKS #3).

Expected win: eliminates the one **totally uncached** hot path (`inline-helpers`, previously 2×/pass full uncached reparse with zero cache credit — the single largest structural offender) and removes redundant disk reads across 6+ objectives; the extract-constant precedent already proves the pattern is safe and byte-identical when done via an optional `source=` parameter.

**Stage 2 — per-session AST/source index passed down explicitly.**
- `compile_objective(project_root, ..., source_index: SourceIndex | None = None)` (new optional kwarg, default `None` ⇒ today's behavior via `indexed_project(root)`): when supplied, `_own_modules`/`candidates()` use the passed index directly instead of each re-querying the global `indexed_project()` dict.
- `run_develop_session` (`develop_session.py:630`): build ONE `SourceIndex` via `indexed_project(root)` before the objective loop (`708-713`), pass it into every `compile_objective(...)` call, and after each objective returns, **refresh** it (`index = indexed_project(root)` again — the fingerprint check naturally rebuilds only if that objective actually wrote files) before handing it to the next objective — makes the sharing explicit and auditable instead of implicit-via-global-dict, and is the prerequisite object Stage 3 mutates incrementally.
- Blast radius: `compile_objective`'s signature (additive-only), `_own_modules` (needs an optional index param mirroring the same default-None pattern), `run_develop_session`'s loop body. Centralized — one function (`_own_modules`) is the single call funnel for nearly every consumer.
- This stage's marginal *perf* win is smaller than it looks (the fingerprint-checked global cache already avoids most redundant rebuilds when nothing changed) — its real value is architectural: turning an implicit memoized function into an explicit passed object is what makes Stage 3's per-file diffing possible, since the object now has an identity a caller can incrementally update.

**Stage 3 — incremental re-parse of changed files only (the actual fix for "per-move whole-project re-parse").**
- `app/engine/source_index.py::_fingerprint()` (152-166): keep as the *authority* for what changed, but change `indexed_project()` (173-189) to **diff** the new fingerprint set against the cached one (`set(new) - set(cached)` for changed/added, `set(cached_rels) - set(new_rels)` for deleted) instead of an all-or-nothing tuple equality check.
- New `SourceIndex.update(project_root: Path, changed: set[str], deleted: set[str]) -> SourceIndex`: re-reads+re-parses only `changed` (routed through `parse_cached`, Stage-1-item-10), drops `deleted` from `modules`/`all_sources`, returns a new index with every OTHER `IndexedModule` object reused byte-identically (same `source`, same `tree` object — untouched, unparsed again).
- `indexed_project()` becomes: compute current fingerprint → if unchanged, return cached (as today); if changed, call `cached.update(...)` and re-cache — replacing the current `SourceIndex.build()` full-rebuild call on any diff.
- Gate this stage behind proof (Stage 1+2 landed, gated, pinned) before merging — it is the highest-risk change (see RISKS).

## RISKS (top 3, with mitigations)

1. **Stale-cache wrong-edit risk (the central "salt" risk).** Any cache reuse — cached source text, cached parsed trees, or an incrementally-updated `SourceIndex` — could hand a planner content that no longer matches the live file (a concurrent external edit, or a write this particular cache didn't observe), producing a plan built against wrong line spans/content. **Mitigation:** every stage keeps the `(path, mtime)` fingerprint check as the *sole* authority for freshness — Stage 3's diff must always compare the *current* full mtime set against the cached one (never trust a caller-supplied "these files changed" list alone), so an out-of-band edit is still detected and invalidates exactly that file. The existing last-line defense, `apply_rename`'s `_stale_plan_reason` (`cross_file_rename.py:816-818`), already refuses to write when expected-old-content doesn't match live disk bytes — this must be preserved untouched through every stage (test 9) so even a cache bug fails closed at apply time rather than corrupting a file.

2. **Behavior drift from changing the population a candidate scan sees.** `_own_modules()`/`SourceIndex` excludes fixtures/tests/non-library files; `_py_files`-based fallbacks (e.g. today's `_suggest_trees(None)`) include them. Naively swapping one for the other (Stage 1 item 9) changes *what counts as a duplicate definition* for uniqueness checks (`suggest_inlines`'s `defs_by_name`, `_dead_param_moves`'s object-ref guard), silently changing WHAT lands, not just how fast. **Mitigation:** the Stage-1 plan explicitly preserves the existing universe via `all_parsed_trees()` (union of the own-set's already-parsed trees + a parse of the residual tests/fixtures from `all_source_texts()`), not a narrowing swap; test 8 pins byte-identical output as a hard regression guard. Any deliberate scope change must be its own separately-reviewed, explicitly-labeled commit with its own red-first test disclosing the delta — never bundled into a "just faster" change, per the North Star's "never fakes green" / honest-attribution discipline.

3. **Cross-cache incoherence when unifying `source_index` with `python_structure`'s `parse_cached`.** The two caches currently have slightly different except-clause sets (`source_index.py:118`: `SyntaxError, ValueError, RecursionError, MemoryError`; `python_structure.py:148`: adds `OSError`) and different degrade semantics for an unreadable file. Routing one through the other without reconciling could turn a gracefully-degraded `tree=None` into an uncaught exception for a class of malformed/unreadable files. **Mitigation:** reconcile the except-clause sets to their union before wiring (Stage 1 item 10), verify the byte-identical `None`-degrade behavior with a dedicated test (test 10) covering the asymmetric exception classes, and land this as a narrowly-scoped, independently-reviewable change separate from the higher-traffic `source=` threading changes so a regression here is easy to isolate and revert.
